# 🏋️ Telegram-бот для учёта тренировок (Workout Bot)

[![Python CI](https://github.com/Evgeniy-SP/workout-bot-new/actions/workflows/ci.yml/badge.svg?branch=main&event=push)](https://github.com/Evgeniy-SP/workout-bot-new/actions/workflows/ci.yml?query=branch%3Amain+event%3Apush)

Персональный бот-дневник тренировок прямо в Telegram: планируешь программы,
записываешь факт, отслеживаешь прогресс, рекорды и получаешь достижения.

## 🚀 Основные возможности (C1)

- **Справочник:** создание тренировок и упражнений (силовые и кардио).
- **Умные подсказки:** бот автоматически подтягивает веса и повторения из прошлой тренировки с указанием даты.
- **Текстовый вес:** можно писать «Своё тело», «Резинка», «10 блоков» вместо чисел.
- **Опциональные упражнения:** разминки/заминки не портят статистику, если их пропустить.
- **Таймеры отдыха:** 60с, 90с, 3 мин, своё время — с фоновыми уведомлениями и автоудалением.
- **Цифровые клавиатуры:** ввод весов и повторений через inline-кнопки.
- **Заметки:** комментарии к упражнению и ко всей тренировке.
- **Умная ротация:** тренировку, которую давно не делал, бот поднимает вверх меню.
- **Архив и безопасное удаление:** нельзя случайно удалить то, что имеет историю.

## 📅 Аналитика (C2.5)

- **Месячный дашборд:** тренировки, подходы, упражнения, общее время, тоннаж.
- **Топ упражнений** месяца по подходам с лучшим результатом.
- **Средний отдых между подходами** (медиана, перерывы > 10 мин не считаются).
- **Средний отдых между упражнениями** (медиана перехода от последнего подхода одного упражнения к первому подходу следующего, перерывы > 20 мин не считаются).
- **График активности** по неделям месяца (тренировки и уникальные упражнения).
- **История и детали:** просмотр любой прошедшей тренировки.

## 🏆 Рекорды и достижения (C2.6)

- **Автодетект рекордов (PR):** бот сравнивает каждый подход со всей предыдущей
  историей упражнения и поздравляет мгновенным уведомлением (автоудаление 15 сек).
  Единые правила сравнения для веса (включая текстовые единицы: кг/блоки/своё тело)
  и для кардио (длительность, когда вес не указан).
- **Строка рекорда на экране подхода:** «🏆 Рекорд: 100 кг от 12.11».
- **14 достижений:** рубежи по числу тренировок (10/50/100/250), месячный ритм
  (12 и 20 тренировок за календарный месяц), разнообразие упражнений (10/25/50),
  рекорды (первый, 10, 50, 3+ за тренировку), рост веса +20% к базе первых 30 дней.
- **Экран «🏆 Ачивки»** в аналитике: с прогрессом по каждому замку, молчаливым
  зачётом прошлых заслуг при первом открытии и кнопкой обновления.

### 📤 Экспорт в CSV (C2.6 Блок 4)
- **Три вида выгрузки:** история упражнения (с экрана прогресса), тренировки
  за месяц (из аналитики), одна тренировка детально (из деталей или экрана
  итогов). Файл приходит документом в чат.
- **Excel-friendly:** UTF-8 с BOM и разделитель «;» — открывается по двойному
  клику в Excel на Windows без мастера импорта; числовые кг с запятой.
- **Детально:** подходы с весом, повторами, длительностью и интервалами
  отдыха; время в формате «часы/минуты»; тоннаж строго в кг (совпадает с
  экраном деталей тренировки).

## 🧠 Ключевая логика (под капотом)

### План vs Факт
- **План (шаблон)** — настраивается в меню «Упражнения»: целевые подходы, повторы, вес.
- **Факт (активная тренировка)** — ввод фактических данных не меняет шаблон, а создаёт историю.

### Приоритет истории и плана
- **Вес и повторения** подтягиваются из последнего выполненного подхода («В прошлый раз (дата)» + кнопка автозаполнения).
- **Количество подходов** берётся из шаблона; лишние добавляются кнопкой «Добавить подход».

### Архитектура
```
handlers/   — события Telegram (aiogram 3, Router + FSM)
services/   — чистая бизнес-логика (PR, достижения, аналитика) — без БД и Telegram, легко тестируется
db/         — SQLAlchemy 2.0 async: модели и запросы
```

### Архив
- Архивация прячет упражнение/тренировку из глаз, но сохраняет все подходы и заметки.

## 📦 Технический стек

- **Язык:** Python 3.12
- **Библиотеки:** aiogram 3.x, SQLAlchemy 2.0 (async + asyncpg), Alembic.
- **База данных:** PostgreSQL 16 в Docker-контейнере
- **Тесты:** pytest + pytest-asyncio (SQLite+aiosqlite в памяти), бейдж статуса CI в README, процент покрытия в сводке GitHub Actions.
- **Деплой:** Docker Compose, автоматические дампы БД

## Миграции базы данных

Alembic получает адрес PostgreSQL из `ALEMBIC_DATABASE_URL`. Укажи адрес
отдельной базы перед запуском. Настройки подключения самого бота остаются в `.env`.
Перед запуском новой версии примени миграции к той базе, которую будет использовать
бот. При старте бот проверяет наличие таблицы архива.

Для **пустой тестовой базы** в Git Bash:

```bash
python -m pip install -r requirements.txt
export ALEMBIC_DATABASE_URL='postgresql+asyncpg://USER:PASSWORD@127.0.0.1:PORT/TEST_DB'
python -m alembic upgrade head
python -m alembic current
python -m alembic check
```

Для **копии существующей базы без Alembic** сначала сверь схему с ревизией
`0001`. Если они совпадают, выполни `python -m alembic stamp 0001` и затем
`python -m alembic upgrade head`. `stamp` отмечает ревизию и не исправляет
расхождения. Если схема отличается, сначала подготовь и проверь перенос на
копии. Откат до `base` удаляет таблицы начальной схемы.

Ревизия `0002` добавляет таблицу `monthly_challenge_results`. У каждой цели
месяца своя запись: название, единица, порог, результат, статус и детали.
В следующих месяцах можно выбрать другие цели и пороги без изменения таблицы.
Откат с `0002` на `0001` удаляет эту таблицу вместе с её данными.

Ревизия `0003` закрепляет серверные значения по умолчанию для архивации и
ротации и ограничивает заметки одной записью на пару «тренировка, упражнение».
Если в базе на `0002` уже есть дубли заметок, миграция остановится. Перед
повтором нужно проверить эти записи и согласовать, как их сохранить.

Для старой базы VPS из семи таблиц сначала восстанови свежий боевой дамп
в отдельную базу. После сверки с известной старой схемой выполни на копии
`scripts/prepare_vps_0001.sql` через `psql -X -v ON_ERROR_STOP=1`. Скрипт
создаёт `achievements` и два индекса заметок, сохраняя существующие ограничения
и значения по умолчанию. Затем направь `ALEMBIC_DATABASE_URL` на эту копию
и последовательно выполни `stamp 0001`, `upgrade head`, `current` и `check`.
Сверь строки семи исходных таблиц и проверь запуск обеих версий на копии.

## 🗺 Дорожная карта

См. [ROADMAP_C2.md](./ROADMAP_C2.md): C2.7 «Сезоны и ретроспектива» —
сезонные челленджи, доска рекордов «🏅 Лучшее», годовая и сезонная ретроспектива.

Фиксированный архив челленджей начинается с декабря 2026. С января 2027 по умолчанию
ежемесячно повторяются две цели: 12 завершённых тренировок и личные рекорды в 3 разных
упражнениях. Для отдельных месяцев набор и пороги можно задать в `MONTHLY_GOAL_OVERRIDES`
в сервисе ачивок. Новым показателям нужно правило подсчёта. Прошлые месяцы доступны
в «Ачивках» по кнопке «Архив челленджей».

Зачёт идёт по дате начала тренировки в МСК. На стыке месяцев новый зачёт открывается
сразу, а предыдущий фиксируется после завершения или отмены оставшихся тренировок.
После простоя бот закрывает пропущенные периоды при запуске.

Перед обновлением бота на VPS запланированы сверка схемы рабочей БД, резервная
копия, пробная миграция на восстановленной копии и проверка сохранности истории.
