# LEARNING.md — Память и уроки проекта

Этот файл помогает Codex учитывать **подтверждённый опыт предыдущих сессий**. Он относится только к текущему проекту.

**Правила ведения:**
- Читать в начале работы над проектом (см. `AGENTS.md`).
- Добавлять выводы только после реально выполненной задачи, проверки или явной корректировки пользователя.
- Записывать кратко: **контекст → правило/вывод → подтверждение**.
- Избегать повторов, устаревших записей, паролей, токенов и персональных данных.
- Если урок перестал быть актуальным, исправить или удалить запись с пояснением причины.
- Если подтверждённых уроков ещё нет, оставлять этот файл почти пустым.

## Подтверждённые уроки

### 2026-11-22 — Подсчёт тренировок для сезонного челленджа

- Контекст — декабрьская цель на 12 завершённых тренировок.
- Правило — считать каждую завершённую сессию по дате её начала в МСК. Несколько сессий в один день считаются отдельно.
- Подтверждение — тест в `tests/test_achievements_db.py` покрывает совпадающие даты, границу месяца по МСК и незавершённую сессию.

### 2026-11-22 — Уникальные упражнения в сезонном челлендже PR

- Контекст — декабрьская цель на три разных упражнения с личным рекордом.
- Правило — сравнивать подходы с предыдущей историей того же названия и типа упражнения, учитывая только завершённые тренировки. Несколько рекордов одного упражнения дают один балл, а в зачёте показывается последний PR за период.
- Подтверждение — тесты проверяют сравнение с прошлым месяцем, обновление результата при рекорде на повторы и в другой единице, исключение незавершённой тренировки и выдачу награды за третье упражнение.

### 2026-11-22 — Границы зимней ретроспективы

- Контекст — сезонные итоги рядом с годовыми.
- Правило — зима относится к декабрю года начала и январю–февралю следующего года. Декабрь входит и в зимний сезон, и в свой календарный год.
- Подтверждение — тест в `tests/test_analytics_service.py` проверяет стык осени и зимы, переход через Новый год и високосный февраль.

### 2026-11-22 — Подключение Alembic к существующей схеме

- Контекст — у бота уже есть базы, созданные через `create_all()`.
- Правило — на пустой базе применять `upgrade head`; существующую схему сначала сверить с исходной ревизией, затем отметить `stamp 0001` при совпадении. Адрес для Alembic задаётся явно через `ALEMBIC_DATABASE_URL`.
- Дополнение — с подключением архива бот проверяет наличие таблицы при запуске. Новую базу готовят миграциями, а существующую сначала сверяют с `0001`.
- Подтверждение — на временном PostgreSQL 16 проверены начальная ревизия, переход с `0001` на `0002` и сохранность тестовой записи. `alembic check` не нашёл расхождений; повторная запись той же цели за тот же месяц была отклонена.

### 2026-11-22 — Итоги месяца хранятся по целям

- Контекст — типы целей и пороги могут меняться от месяца к месяцу.
- Правило — хранить название, единицу, порог, результат и детали в записи конкретной цели за месяц. Архив использует сохранённые значения.
- Подтверждение — на временном PostgreSQL 16 сохранены два месяца с разными порогами и целями, включая секунды кардио и дробный тоннаж. Изменение порога в январе не затронуло декабрьскую запись.
- Дополнение — итог сохраняется одной транзакцией на пользователя, с блокировкой его строки. Интеграционная проверка на PostgreSQL подтвердила однократное закрытие и выдачу награды при двух одновременных вызовах. Тесты SQLite проверяют тренировку через полночь и сохранение результата после удаления тренировки из истории.
